## 1. できるようになること

1. **設定を保存（.json）**: 今の設定を JSON ファイルとして保存する。
2. **設定を読み込む**: 保存した JSON を読み込み、今の設定と入れ替える。読み込んだデータはそのまま使い、新しい設定で描き直す。
3. **前回の設定の自動復元**: 設定を変えるたびにブラウザ（localStorage）に控えておき、次にページを開いたときに戻す。データは戻さない（ファイルは選び直す）。
4. **初期設定に戻す**: すべての設定を既定値に戻す（確認のダイアログを出す。データはそのまま）。

使い方の例: 論文用に整えた図の設定を保存しておき、別の日の測定データ（同じ形式の CSV）を読み込んでから設定を読み込むと、同じ体裁の図になる。

## 3. 設定ファイルの形

```json
{
  "format": "matplotlib-gui-settings",
  "savedAt": "2026-11-15T10:00:00+09:00",
  "files": [
    {"name": "data_0901.csv", "sheet": "", "columns": 5},
    {"name": "ref.xlsx", "sheet": "Sheet2", "columns": 3}
  ],
  "settings": { "version": 4, "load": {...}, "plot": {...}, "axes": {...}, "series": [...], ... }
}
```

- `settings` は今の設定オブジェクトそのもの（version 4）。中身の意味は変えない（スキーマは version 4 のまま）。
- `files` は、保存したときに読み込んでいたファイルの名前・シート・列数（ファイルの列だけ。計算した列は含まない）。名前とシートは記録として残すだけで、読み込むときには使わない。列数は、計算した列の番号を合わせるのに使う（§4.4）。
- データ元の id は、保存するときに位置の番号にそろえる。`load.files` の k 番目（0 始まり）の id を `d{k+1}` に書き換え、系列と計算した列の `source` も同じく書き換える（`""` は `""` のまま）。こうすると、読み込むときは「`dN` = データN」として扱える（§4.3）。
- 含めないもの: データ本体、Pythonコードタブの編集中のコードとモード、直近に適用したスタイルプリセット（もともと設定に入れていない。§13.2）、区分・カードの開閉。
- `settings` だけの JSON（`{"version": 4, "plot": ..., ...}`）も読める（`files` が無いものとして扱う）。

## 4. 読み込むとき

### 4.1 形の検査（この段階で失敗したら、何も変えない）

- 1 MB を超えるファイル → 「設定ファイルが大きすぎます（1 MB まで）。」
- JSON として読めない → 「設定ファイルを読み込めませんでした: JSON の形式ではありません。」
- 設定ではない（`settings` も、`plot`・`series` などの項目も無い） → 「設定ファイルではありません。…」
- `version` が 1〜4 でない（5 以上など） → 「この設定ファイルは新しい版のアプリで作られたため、読み込めません（version 5）。」
- いずれも `#status` に `error` で出す（`field` は「設定ファイル」）。

### 4.2 足りない項目を補う（JS の純粋なモジュール `js/settings-io.js`）

- 移行は Python の `migrate_settings` と同じ規則にする: v1 で `save.dpi` が無ければ 120、v1・v2 で `load.parseDates` が無ければ false、そのうえで version を 4 にする。
- 既定値（`DEFAULT_SETTINGS`）の形に合わせて、足りない項目を既定値で補う。配列（系列・注釈・近似曲線・計算した列・パネル）は、要素ごとに要素の既定値で補う。知らない項目は捨てる。
- 値そのもの（グラフの種類の名前、数値の範囲など）は検査しない。不正な値は、今までどおり描画のときに Python が日本語のエラーにする（手で書いた JSON の扱いは、5e の「範囲外のパネル」と同じ）。ただし、形が違う値（オブジェクトのはずの所に数値がある、など）は既定値にする。
- 系列が1つも無ければ、既定の系列を1つ作る。id が空・重複している系列・注釈・近似曲線・計算した列には、新しい id を振る。state の連番（`s` / `a` / `f` / `c`）は、読み込んだ id の最大の番号から続ける（新しく足したものと重ならない）。
- この補い方で作った設定を Python の `parse_settings` に通した結果が、元の JSON を通した結果と同じになることを、単体テストで確かめる（v1〜v4 の例）。

### 4.3 データ元の対応（位置で合わせる）

- 読み込んだデータのファイルとシートは、今のまま変えない（`load.files` は今の一覧を使う）。読込の設定（区切り文字・ヘッダ・読み飛ばす行数・桁区切り・小数点・コメント記号・日時の認識）は設定ファイルのものになるので、ファイルを読み込んでいれば全部を読み直す。
- 系列・計算した列のデータ元 `dN` は、今の一覧の N 番目のファイルにする（ファイル名では合わせない。同じ形式の別のファイルに使うのが主な使い方のため）。→ §8 Q3
- 今の一覧に N 番目のファイルが無いときは、その系列のデータ元をデータ1に戻し、X・Y を自動に戻して、注意を出す（「系列2: 設定のデータ2に当たるファイルが無いため、データ元をデータ1に戻し、列を自動に戻しました。」）。計算した列は、今の「ファイルを外したとき」と同じくデータ元を先頭に戻す。
- ファイルをまだ読み込んでいないとき（自動復元の直後など）は、`dN` を残しておく。次にファイルを選んだとき（一覧が空の状態から）に、選んだ順に付く id（d1, d2, …）とそのまま対応する。
  - そのため `selectFiles` の「置き換え」で、**一覧が空だったときに限り**、新しい一覧にある id を指すデータ元は空に戻さない（今は常に空に戻している。一覧が空のとき、データ元が空でないのは復元した設定だけなので、今までの動作は変わらない）。
  - 読込が終わったとき、一覧に無い id を指すデータ元が残っていれば、上と同じくデータ1に戻して注意を出す（今までの操作では起きない状態なので、今までの動作は変わらない）。

### 4.4 列の番号

- 列は今までどおり列番号（`__idx__N`）で持つ。今のファイルに無い列は、読込のあとの既存の処理（`reconcileColumns`）が自動・空に戻す。
- 計算した列の番号は「ファイルの列数 + 位置」なので、保存したときとファイルの列数が違うと、別の列を指してしまう。そこで、`files[].columns`（保存したときの列数）を「前回の列数」として扱い、今の読み直しで列数が変わったときの規則（`shiftForFileColumnChange`）で付け替える。`files` が無い JSON では、今の列数と同じとみなす。

### 4.5 読み込んだあと

- state をまるごと入れ替え、通知 `settings-replaced` を出す。`main.js` は画面を state から全部描き直す（入力欄、系列・注釈・近似曲線・計算した列のカード、パネル、図の単位、パレット、DPI、日時の書式、表示の出し分け）。
- `bridge.js` は、ファイルを読み込んでいれば全部を読み直し（そのあと今までどおり描く）、無ければ「設定を読み込みました。ファイルを読み込むと、この設定で描きます。」を出す。欧文フォントが変わっていれば、今までどおり取得を始める。
- 編集モードのときは、設定（画面）だけを替え、図とコードは変えない（A8。「編集中のため反映されません」）。
- 直近に適用したスタイルプリセット（新しい系列に引き継ぐ値）は忘れる。

## 5. 前回の設定の自動復元

- 設定が変わるたびに、0.5 秒後に localStorage（キー `mplgui.lastSettings`）へ、§3 と同じ形で書く（`pagehide` のときにも書く）。ただし、ファイル名は書かない（`files` は列数だけ、`settings.load.files` は空にする）。データ元は §3 と同じく位置の番号にそろえる。
- ページを開いたとき、state を作った直後（画面を描く前）に読み、§4 と同じ手順で設定にする。データは読み込まれていないので、§4.3 の「まだ読み込んでいない」場合になる。
- 戻したときは `#status` に `ok` で「前回の設定を復元しました。既定に戻すには「初期設定に戻す」を押してください。」と出す。
- 読めない・新しい版の値だったときは、既定の設定で始め、キーを消して、警告「前回の設定を読めなかったため、初期設定で始めます。」を出す。
- localStorage が使えない（例外を投げる・プライベートモード）ときは、何もしない（今までどおり既定の設定で始める）。
- 復元するかの切り替えは置かない（常に復元する）。→ §8 Q1
- 同じブラウザでページを2つ開いていると、後から書いたほうが残る。

## 9. 実装での変更（2026-11-15）

- 読み込んだ設定の id は `s1` / `a1` / `f1` / `c1` の形に限り、それ以外は振り直す（§4.2 の「空・重複」に加えて）。id がカードの HTML と要素の id にそのまま入るので、細工した設定ファイルで画面に HTML を差し込ませないため。形の違う系列の id を振り直したら、その系列を指す近似曲線も新しい id にする。
- 控えが既定の設定と同じなら、localStorage のキーを消す（§6 の「控えも既定の設定になる」を、キーを消すことで実現する。次に開いたときに「前回の設定を復元しました」と出さない）。
- `pagehide` の書き込みは、そのページで設定が変わったときだけにした（変えずに閉じても控えを書き直さない）。
- 設定ファイルのエラーには `field` を付けない（`#status` に欄名を出す仕組みが無いため）。設計で「…」としていた文は「設定ファイルではありません。このアプリの「設定を保存（.json）」で保存したファイルを選んでください。」、1〜4 でない整数以外の version は「設定ファイルのバージョン（X）に対応していません。」にした。
- 当たるファイルが無い計算した列の注意は「計算した列N: 設定のデータNに当たるファイルが無いため、データ元を先頭のファイルに戻しました。」にした。
