計測スクリプト: `tests/perf/bench.py`（Playwright 同期 API。pytest では収集されない）。
再実行: `uv run python tests/perf/bench.py --reps 5 --json tests/perf/out/result.json`
（`--headed` でヘッドあり実行、環境変数 `E2E_SERVE_DIR` で配信ディレクトリを切替。出力先 `tests/perf/out/` は git 管理外）

### 計測方法

- **コールド起動**: 反復ごとに新規ブラウザコンテキスト（HTTP キャッシュ空）で `goto` し、Python 側が `window.requestRender` を登録して操作可能になるまで。
- **ウォーム起動**: 同一コンテキストで1回読み込んでキャッシュを温めた後、反復ごとに新規ページで再ナビゲーション（HTTP キャッシュ有効）。Python／Pyodide の初期化は毎回走るので、短縮されるのはダウンロード分のみ。
- **描画**: 実行時に生成した 10,000 行（X 1列 + Y 5列）の CSV を使用（コミットしない）。系列カード5つ（X=x列、Y=y1〜y5）を設定。キャッシュを温めたコンテキストで反復ごとに新規ページ。
  - 初回: ファイル選択 → 自動読込 → 最初のプロット表示まで。
  - 設定変更: タイトル入力の `input` イベント発行から、`#plotArea` に新しい画像が表示されるまで（ページ内 `performance.now()`）。250ms のデバウンスを含む。
  - 保存: 保存ボタンのクリックからダウンロード開始まで（PNG）。

## PyScript 2026.7.3 移行直後

計測条件はベースラインと同じ（同一マシン・Chromium 153.0.8010.12・実ネットワーク・N=5）。
対象コミット: `30aee0d`（PyScript 2026.7.3 / Pyodide 314.0.3 = Python 3.14.2、pandas 3.0.2、matplotlib 3.10.8、`pyscript.toml` 使用）。
計測日: 2026-10-07。

| 項目 | 中央値 | 最小 | 最大 | ベースライン中央値 | 比 |
|---|---:|---:|---:|---:|---:|
| コールド起動 | 4,076 | 4,015 | 6,420 | 3,424 | +19% |
| ウォーム起動 | 3,623 | 3,573 | 3,726 | 2,881 | +26% |
| 初回ファイル読込 → 最初のプロット | 422 | 389 | 435 | 417 | +1% |
| 設定変更 → プロット更新（デバウンス込み） | 556 | 550 | 566 | 413 | +35% |
| 同上（デバウンス 250ms 除く） | 306 | 300 | 316 | 163 | +88% |
| 保存（PNG、クリック → ダウンロード開始） | 330 | 323 | 349 | 206 | +60% |

備考:
- 起動・再描画・保存のいずれも悪化した。起動時間は要件（8章: F6 の現状値より悪くしない）を満たしていないため、後続フェーズでの改善対象（フォント取得の遅延、キャッシュ、描画の無駄の削減など）とする。
- 再描画の増加は、matplotlib 3.5.2 → 3.10.8 と Python 3.12 → 3.14、pandas 2 → 3 の差によるとみられる（未切り分け）。
- 起動時のコンソールエラー `Failed to load resource: net::ERR_INVALID_URL` は移行前の `<py-script>` が原因だった。`<py-script>` の中身が HTML としてパースされ、Python 文字列中の `<img alt="plot" src="data:image/png;base64,{encoded}" />` が実際の `<img>` 要素になり、src が不正な URL として読み込まれていた。`<script type="py">` では中身が HTML として解釈されず、移行後は発生しない（旧版には「`<script type="py">` を使うように」という PyScript の非推奨警告も出ていた）。

### 分析

プロファイリング調査（A/B、n=4〜6）で、起動の差の由来を切り分けた。

- ウォーム起動がベースラインより約 +0.5〜0.6 秒遅い差は、ランタイム自体に由来する。内訳の目安は、Pyodide 314 / Python 3.14 の起動で +150〜170 ms、パッケージの読込で +100〜140 ms、`import matplotlib` で +190〜250 ms、`import pandas` で +約100 ms。
- PyScript を介さない素の Pyodide ページでも同じ差が出る。アプリ側のコードが起動時間を増やしているわけではない。

Phase 1 で行った改善:

- openpyxl の遅延導入: バージョン固定の wheel URL と `packages_cache = "passthrough"` により、起動時に micropip を使わない。コールド起動で約 -340 ms（移行直後 4,076 → 3,650 ms の大部分）。代わりに、初めて .xlsx を読むときに wheel を取得する（上表の 336 ms を含む）。
- 保存・描画前に matplotlib 3.10 の `PlaceHolderLayoutEngine` を外す: 描画・保存で約 -65 ms、出力はバイト単位で同一。
- Agg バックエンドを使う（`matplotlib_pyodide` のバックエンドを使わない）。
- 日本語フォントを Cache Storage に保存する: 2回目以降の訪問では約16 MB の再ダウンロードが発生しない（E2E テストで確認）。

ベースラインとの比較では、起動（コールド・ウォーム）、再描画、保存はいずれも悪い。移行直後よりは改善したが、ベースラインには戻っていない。要件（8章）の「起動時間を F6 の現状値より悪くしない」は満たしていない。初回ファイル読込 → 最初のプロットは良い（上の注記のとおり参考値）。

ウォーム起動に残る差（約 +0.5 秒）をどう扱うか（許容する、Pyodide の旧版へ戻す、など）は、オーナーの判断待ち。
