### 2.2 全体に通す規則

1. **表示していない設定は使わない。** グラフの種類や軸の種類で入力欄を隠す・無効にするときは、その値を図に使わない（値は消さないので、戻せば効く）。表示している設定どうしが組み合わせとして使えないときは、日本語のエラーで案内する（Phase 4 の「日時の X と対数軸」と同じ）。
2. **列は「系列のデータ元＋列番号」。** エラーバー・塗りつぶし帯・色分けの列は、系列のデータ元の列から選ぶ（行が対応している必要があるため。ほかのファイルの列は選べない）。設定では `__idx__N`。新しい項目は `""` か `__idx__N` だけを受け付ける（列名での指定は受け付けない）。
3. **データを見て決めることは dataprep、コードの文字列は codegen。** 軸の種類（数値・対数・日時・文字列）によって、どの設定が効くかは dataprep が決め、`PlotPlan` に入れる。codegen はそれを文字列にするだけにする。
4. **既定の設定では、生成コードの文面を Phase 4 と同じにする。** 新しい行は、その機能を使ったときだけ書く。
5. **信頼できない文字列は `literal()` / `comment_text()` だけを通す。** 注釈の文字、式、日時の範囲、書式の指定、列名（コメント）も同じ。式（G6・G10）は利用者の文字列をコードに入れず、解釈した木から決まった形のコードを作る（§2.6）。

### 2.3 codegen の広げ方

- **節の番号は `_Builder.section()` が自動で振る**（5b 以降、使うときだけ「注釈」などの節が入る。使わなければ番号は今と同じ）。
- **系列ごとの付属物**（エラーバー 5a、塗りつぶし帯 5b、近似曲線 5b）は、`SERIES_EMITTERS` の各関数から呼ぶ小さな関数に分ける。描く順は「塗りつぶし帯 → エラーバー → 系列本体 → 近似曲線」（系列本体が帯やエラーバーの上に来る）。
- **軸の設定は軸ごとの関数にする。** `_emit_axis_ticks(b, var, which, axis_plan)` のように、Axes の変数名を引数で受ける。G9 では、パネルごとにこれを呼べば済む（`ax` 固定の書き方を増やさない）。
- 手順（`b.step`）を、エラーバー（「系列Nのエラーバー」）と目盛（「X軸の目盛」など）に足す。実行時の失敗を、項目名つきの日本語メッセージにする。
- G7・G8 は `SERIES_EMITTERS` に種類を足す。種類ごとに X の意味が変わる（ヒストグラムは X なし、横棒は値が横軸、箱ひげ図は系列ごとに1つの箱）ので、dataprep が種類ごとの計画を作る（`PlotPlan.kind_plan` のような種類別の小さな dataclass）。

### 2.4 dataprep の広げ方

- `SeriesPlan` に `y_err` / `x_err`（`ErrorPlan | None`）を足す（5a）。5b で `fill`、5c で `color_index` などを足す。
- `PlotPlan` に `axes: AxesPlan` を足す（5a）。`AxesPlan` は `x` / `y` / `y2` の `AxisPlan` を持つ。`AxisPlan` は、その軸の種類（`number` / `log` / `datetime` / `category`）と、実際に効く設定（主目盛・副目盛・書式・反転・範囲）だけを持つ。G9 では `PanelPlan` ごとに `AxesPlan` を持たせる。
- データ由来の警告とエラーは、今までどおり日本語で `PlotPlan.warnings` / `UserError` にする。

### 2.5 「注釈・解析」の区分（5b で作る）

- 位置は「体裁」と「保存」の間（要件 6 章の順）。id は `#sectionAnalysis`、既定で開く（折りたたみの状態は今の仕組みで localStorage に残る）。
- 中身の予定:
  - 注釈（G4、5b）: 「+ 注釈を追加」で、文字・水平線・垂直線・範囲の帯（横・縦）を足す。
  - 近似曲線（G5、5b）: 「+ 近似曲線を追加」で、対象の系列とモデルを選ぶ。系列を削除したら、その近似曲線も消す。
  - 計算した列（G6、5c）: 「+ 列を追加」で、データ元・列名・式を入れる。
  - 任意関数のフィッティング（G10、5d）: 近似曲線のモデルに「任意の式」を足す。
- エラーバー（G1）と系列のスタイル（G3）は系列ごとの設定なので、系列カードに置く。

### 2.6 G3–G10 の概略

**G3（系列のスタイル）**: マーカー形状（`auto` は今の動き: line は点サイズ > 0 なら丸、scatter は丸）、透明度、塗りつぶし帯（`fill_between`。下限・上限の列を系列のデータ元から選ぶ）。並べ替え（↑↓）と複製は JS だけの操作（配列の順番＝描く順。複製は新しい id）。

**G4（注釈）**: 文字（`ax.text`。データ座標か、図の中の割合 0〜1）、水平線・垂直線（`axhline` / `axvline`）、範囲の帯（`axhspan` / `axvspan`）。X の値は、X が日時の軸なら 5a で作る日時の解釈（`pd.Timestamp(...)`）を使う。Y は第2Y軸にも置ける。

**G5（近似曲線）**: `np.polyfit`（線形は1次）。描く範囲は X の最小〜最大を 200 点。式と R² は、生成コードの実行時に係数から作る（`f"y = {coef[0]:.4g}x + …"`。書式は codegen の固定文字列で、利用者の文字列は入らない）。表示先は凡例・図の中・なし。X が日時・文字列の系列は近似できない（日本語のエラー）。

**G6（式で新しい列）**: `eval` も Python の `ast` も使わず、許可した要素だけの小さな文法を自前で解釈する（新しいモジュール `py/mplgui/expr.py`。`pyscript.toml` に追加）。

- 文法: 数値、列の参照、`+ - * /`、`**`（`^` も可）、括弧、単項マイナス、許可した関数だけ。
  - 要素ごとの関数: `abs` `sqrt` `exp` `log`（自然対数）`log10` `sin` `cos` `tan`
  - 集計（列 → 1つの値）: `min` `max` `mean` `median` `std` `first` `last`
  - 系列の処理: `rolling_mean(式, 窓の幅)`（移動平均。窓の幅は整数の定数）、`diff`、`cumsum`
- 列の参照は `[N]`（画面の「列名 [N]」の N。0 始まり）。要件の例（`B*1000`、`B/C`）に合わせて、Excel の列記号（`A` = `[0]`、`B` = `[1]` …）も使えるようにする。列名での参照は受け付けない（同名の列を区別できないため）。
- 長さ（200 文字まで）と入れ子の深さ（30 まで）に上限を設ける。数値は有限の値だけ。
- 解釈した木からコードを作る。数値は `literal()`、列は `pd.to_numeric(df.iloc[:, N], errors="coerce")`、関数は決まった形（`np.sqrt(…)`、`(…).rolling(5, center=True).mean()` など）。利用者が書いた式の文字列は、`comment_text()` を通してコメントにだけ入れる。0 で割った結果（±inf）は NaN にする。
- 正規化・オフセット・移動平均は、式の入力欄に雛形を入れるボタンにする（例: `[1] / max([1])`、`[1] - first([1])`、`rolling_mean([1], 5)`）。
- 新しい列は、そのデータ元の DataFrame の末尾に足す（列番号 = 元の列数 + 順番）。系列の X・Y の選択肢にも出る。dataprep も同じ木を pandas で評価して、数値にならない値の警告や列の範囲外を確かめる。

**G7–G9（グラフの種類とサブプロット）**:

- グラフの種類は今と同じく図全体で1つ（`plot.type`）。`SERIES_EMITTERS` に `step`（`drawstyle="steps-post"` など）、`barh`、`barStacked`、`hist`、`scatterColor`（第3列で色分け。全系列で色の範囲とカラーバーを共有）を足す。
- 横棒では、物理的な軸の設定をそのまま使う（X軸の設定＝横軸＝値の軸、Y軸の設定＝縦軸＝カテゴリ）。軸ラベルの自動の値だけ入れ替える。
- サブプロット（G9）: `fig, axs = plt.subplots(行, 列, squeeze=False)`。系列ごとにパネルを選ぶ。軸の目盛・スケールの設定は全パネル共通（`axes`）で、タイトルと軸ラベルはパネルごとに上書きできる（`panels`）。グラフの種類は全パネル共通。(a)(b) のラベルは `ax.text(…, transform=ax.transAxes)` で付ける。第2Y軸の変数名は、パネルごとに `ax_a2` のようにする（§2.3 の「Axes の変数名を引数で受ける」形で実現する）。

**G10（任意関数のフィッティング）と U5（scipy）**: 要件 4.2（生成コードは pandas・matplotlib・numpy だけ）とぶつかるので、案を3つ挙げる。

### 2.7 性能の見込み（10,000 行 × 5 系列、設定変更 → 再描画。現状 465 ms）

- **G1 のエラーバーは `ax.errorbar` を使うと間に合わない。** ブラウザで実測すると（編集モードで同じ図を描いて比較、N=5）、`ax.errorbar` は1系列あたり 10,000 本の線分を別々の図形として作るので、5 系列で **+約 1,040 ms**（合計 約1.5 秒）になる。各系列の縦線を NaN で区切った1本の線にまとめ、端の横線を点の記号（`marker="_"`）で描く方法なら **+約 150 ms**（合計 約0.6 秒）で、見た目は `ax.errorbar` と同じになる。5a はこの方法を推奨する（§3.2）。X・Y の両方向でも 1 秒以内の見込み。
- G2（目盛）は、目盛の数を 100 本までに抑えるので、ほぼ影響なし。間隔が小さすぎる指定をそのまま描くと、3,000 本の目盛で 1.6 秒、100 万本では止まる（実測）ため、上限は必須。
- G3 の塗りつぶし帯は多角形1つなので軽い。G5 の `np.polyfit`（10,000 点）は数 ms。G7 のヒストグラム・色分け散布図も今の散布図と同程度。G8 のバイオリン図は密度推定があるので 5d で計測する。G9 は `tight_layout` がパネル数に比例して重くなる。G10 は初回の scipy の読み込み（数秒）が別にかかる。

### 3.2 G1 エラーバー

**指定のしかた**: 系列ごとに、Y 方向と X 方向をそれぞれ「なし / 固定値 / 列」から選ぶ。既定は上下（左右）で同じ値。「上下で別の値」にすると、上（+）と下（−）を別に指定できる。列は系列のデータ元から選ぶ（§2.2）。列の値は「誤差の大きさ」（0 以上）として扱う。

**描き方**:

- line / scatter: 系列本体の直前に、エラーバーを描く関数 `draw_error_bars` を呼ぶ。縦線（X 方向なら横線）を NaN で区切った1本の線にまとめ、端の横線（縦線）を点の記号で描く。見た目は `ax.errorbar(..., capsize=…)` と同じで、10,000 点でも速い（§2.7）。この関数は、エラーバーを使うときだけスクリプトの冒頭（import の後）に定義する。pandas・matplotlib・numpy だけを使い、「`ax.errorbar` と同じ図を、点が多くても速く描くための関数」とコメントを付ける。
- bar: `ax.bar(..., yerr=…, capsize=…, ecolor="black")`（棒グラフの標準の書き方。棒の本数は多くないので速さは問題にならない）。X 方向は使わない（入力欄を隠す）。複数系列の棒は `bar_data` に誤差の列を足す。
- 色は系列の色（棒グラフは黒）。線幅は系列の線幅。
- 重なり順: 系列本体を上にする（scatter のときはエラーバーの `zorder` を 1 にして、点を上に描く）。
- 第2Y軸の系列は `ax2` に描く。
- 凡例: 今までどおり系列の線・点・棒だけを出す（エラーバーの記号は出さない）。系列の描き方を変えずに済み、エラーバーの有無で凡例が変わらないため。

**データの扱い**:

| 場合 | 扱い |
|---|---|
| 誤差の列が空欄 | その点のエラーバーだけ描かない（警告なし） |
| 数値にできない値（A7） | その点のエラーバーだけ描かない。系列ごとに件数と例を警告する（桁区切り・小数点のヒントも今と同じく付ける） |
| 負の値 | その点のエラーバーだけ描かず、件数を警告する（誤差の大きさは 0 以上のため）。生成コードでは `y_err = y_err.where(y_err >= 0)` で NaN にする |
| 系列の点が欠けている行（`ok` が偽） | 点を描かない行のエラーバーも描かない |
| 対数軸で下端が 0 以下 | エラーではない。下端は軸の下端まで伸びる（matplotlib の既定の `clip`。軸の範囲は正の値だけで決まる） |
| X が日時・文字列の系列で X 方向を指定 | 日本語のエラー（「系列1: X が日時（文字列）の列のときは、X 方向のエラーバーは付けられません」） |
| 固定値・列が未入力 | 日本語のエラー（`field` は「系列1のY誤差」など） |
| データ元を替えた | X・Y と同じく、誤差の列を空に戻す（方式はそのまま。列を選び直すよう日本語のエラーで案内する） |

**生成コードの例**（line、Y 方向・列・上下で同じ）:

```python
# エラーバーを描く関数（ax.errorbar(x, y, yerr=…, capsize=…) と同じ見た目。点が多くても速く描ける）
def draw_error_bars(ax, x, y, lower, upper, *, direction, color, linewidth, capsize, zorder=2):
    ...  # 区切りに NaN を入れた1本の線（縦線または横線）と、両端の短い線（点の記号）を描く

# 系列1: X = 時間 [0]、Y = 温度 [1]
x = df.iloc[:, 0]
y = pd.to_numeric(df.iloc[:, 1], errors="coerce")  # 数値にできない値は NaN にする
ok = x.notna() & y.notna()  # X か Y が欠けている行は描かない
y_err = pd.to_numeric(df.iloc[:, 3], errors="coerce")  # Y の誤差: 標準偏差 [3]（数値にできない値は NaN）
y_err = y_err.where(y_err >= 0)  # 負の値は NaN にする（その点のエラーバーは描かない）
draw_error_bars(ax, x[ok], y[ok], y[ok] - y_err[ok], y[ok] + y_err[ok], direction="y", color="#FF4B00", linewidth=2.0, capsize=3.0)
ax.plot(x[ok], y[ok], color="#FF4B00", linewidth=2.0, linestyle="solid", label="温度")
```

上下で別の値なら `y_err_plus` / `y_err_minus` の2列、固定値なら `y[ok] - 0.2, y[ok] + 0.5` のように書く。

### 3.3 G2 目盛

軸ごと（X・Y・第2Y）に、次を設定できるようにする。

| 設定 | 数値の軸 | 対数軸 | 日時の X | 文字列の X（line / scatter）・棒グラフの X |
|---|---|---|---|---|
| 主目盛の間隔 | `ticker.MultipleLocator(間隔)` | 使わない（入力欄を無効にする。主目盛は 10^n ごと） | 整数 + 単位。`mdates.YearLocator(base=n)` / `MonthLocator(interval=n)` / `DayLocator(interval=n)` / `HourLocator` / `MinuteLocator` / `SecondLocator` | 「何個おきにラベルを出すか」（整数）。`MultipleLocator(n)`、複数系列の棒は `tick_step = n` |
| 副目盛 | 自動・表示・なし。表示のとき分割数（2〜10、空欄は自動）で `AutoMinorLocator(n)` | 自動・表示・なし（表示は 2〜9 × 10^n。分割数は使わない） | 数値の軸と同じ | 使わない（隠す） |
| ラベルの書式 | 自動 / 小数（`FormatStrFormatter("%.2f")`）/ 指数表記（`"%.1e"`）/ 10^n 表記（`ScalarFormatter(useMathText=True)` と `set_powerlimits((0, 0))`。軸の端に ×10^n をまとめて書く） | 自動（10^n）/ 小数 / 指数表記 / 10^n（`LogFormatterSciNotation`）。自動以外のとき、副目盛の数字は消す | 使わない（Phase 4 の「日時の表示書式」を使う） | 使わない |
| 軸の反転 | `ax.invert_xaxis()` など。範囲を指定していても使える | 同左 | 同左 | 同左 |

- **上と右の枠線**（`plot.spines`）: `ax.spines["top"].set_visible(False)` など。第2Y軸があるときは、`ax2` の上の枠線も消す。第2Y軸があるときは右の枠線（第2Y軸の線）は消せないので、チェックボックスを無効にして、そのことを補足に書く。
- **既存のグリッドとの関係**: 「副目盛線を表示」は今までどおり「副目盛の位置に線を引く」。副目盛が「自動」の軸は今の動きのまま（副目盛線を表示するときだけ副目盛を出す。対数軸は副目盛線を表示しないとき副目盛を消す）。「表示」「なし」を選んだ軸は、副目盛線の設定にかかわらずそれに従う（「なし」で副目盛線を表示すると、その軸には副目盛線が出ない）。今の `ax.minorticks_on()` は軸ごとの副目盛の指定を上書きしてしまう（実測）ので、軸ごとに指定がある場合は軸ごとの書き方にする。すべて「自動」なら、生成コードは今と同じ文面。
- **目盛が多すぎるとき**: dataprep が、データの範囲（指定した範囲、エラーバーの端を含む。棒グラフは 0 を含む。余白 5% を足す）と間隔から、主目盛の本数を見積もる。100 本を超えたら日本語のエラーにする（「X軸の主目盛の間隔が小さすぎます（目盛が約N本になります。100本まで）。間隔を大きくするか、空欄（自動）にしてください。」、`field` は「X軸の主目盛の間隔」）。文字列の X はカテゴリの数、日時は期間を単位の長さ（月は 30.44 日、年は 365.25 日）で割って見積もる。副目盛の分割数は 10 までなので、副目盛も最大で約 1,000 本（matplotlib が警告を出す `MAXTICKS` の目安）に収まる。
- **整数でないといけない場合**: 日時の X と文字列の X の主目盛の間隔は整数。整数でなければ日本語のエラー。
- **0.1 刻みの誤差**: `MultipleLocator(0.1)` の目盛の位置は 0.30000000000000004 のような値になるが、ラベルは「自動」でも「小数1桁」でも 0.3 と出る（実測）。テストで、範囲の端（0 と 1.0）が欠けないことと、ラベルの文字列を確かめる。

**生成コードの例**:

```python
ax.xaxis.set_major_locator(ticker.MultipleLocator(0.5))  # X軸の主目盛: 0.5 ごと
ax.xaxis.set_minor_locator(ticker.AutoMinorLocator(5))  # X軸の副目盛: 主目盛の間を 5 等分
ax.xaxis.set_major_formatter(ticker.FormatStrFormatter("%.2f"))  # X軸の数字: 小数 2 桁
ax.invert_yaxis()  # Y軸を反転する（上が小さい値）
ax.spines["top"].set_visible(False)  # 上の枠線を消す
```

### 3.4 X が日時の列のときの X 軸の範囲指定（5a で扱う提案）

- Phase 4 では「X が日時のときは X 軸の範囲を指定できない（エラー）」にした。G2 で日時の目盛の間隔を扱い、5b の注釈でも日時の座標が要るので、5a で日時の範囲指定を入れる。
- X が日時の列のときは、数値の最小値・最大値の欄（`#xMin` / `#xMax`）を隠し、日時の欄（`#xDateMin` / `#xDateMax`、文字の入力欄、例「2026-01-31 12:00」）を出す。X が日時でないときは逆。隠した欄の値は使わない（§2.2 の規則）。
- 生成コード: `ax.set_xlim(left=pd.Timestamp("2026-01-01 00:00:00"), right=pd.Timestamp("2026-02-01 00:00:00"))`。文字列は settings で解釈して正規化した値を `literal()` で書く。
- 対数軸との組み合わせは、今までどおりエラー。
- これに伴い、Phase 4 のテスト（単体: 日時の X と数値の範囲でエラーになること。E2E: `test_datetime.py` の X の範囲指定のエラー）を、新しい動き（日時で範囲を指定できる・数値の範囲は使わない）に合わせて書き換える。

- 種類ごとに使わない項目は検証しない（§2.2）。

### 5.2 G3 系列のスタイル

- **マーカー形状**: line の「自動」は今の動き（点サイズ > 0 なら丸）。形を選んで点サイズが自動のときは、散布図の自動と同じ面積 24 で描く（選んだのに見えない、を防ぐ）。「なし」は点サイズにかかわらず点を描かない（点サイズの欄を無効にする）。scatter の「自動」は今の丸。scatter の「なし」は点が見えなくなるので、日本語のエラーにする。
- **不透明度**: `ax.plot` / `ax.scatter` / `ax.bar` に `alpha=0.5` を足す。エラーバーと塗りつぶし帯には効かない（帯は自分の不透明度を持つ）。欄の名前は「不透明度」（0〜1。1 は透けない）にする（下記の確認事項 4）。
- **塗りつぶし帯**: line / scatter。下端・上端の列は系列のデータ元から選ぶ（§2.2）。値は下端・上端そのもの（誤差の大きさではない）。
  - `ax.fill_between(x[ok], lower[ok], upper[ok], color=系列の色, alpha=0.25, linewidth=0, label="_fill")`。凡例には出さない。
  - 下端・上端が欠けた行では帯が途切れる。数値にできない値は、エラーバーと同じく系列ごとに件数と例を警告する。
  - X が日時・文字列の列でも描ける（CPython で確認した）。第2Y軸の系列は `ax2` に描く。
  - 描く順は「塗りつぶし帯 → エラーバー → 系列本体 → 近似曲線」（§2.3）。
  - データ元を替えたら、下端・上端の列を空に戻し（帯は消える）、そのことをステータスの警告で知らせる。
- **並べ替え・複製**: 系列カードの見出しに「↑」「↓」「複製」を足す（「削除」の左）。JS だけの操作（`state.js` の `moveSeries(id, delta)` / `duplicateSeries(id)`）。
  - 系列の順は、描く順・凡例の順・「系列N」の番号・複数系列の棒の並びに効く。Y が自動の系列は順に未使用の列が割り当たるので、並べ替えると変わることがある（今の規則のまま）。
  - 複製: すべての設定（エラーバー・塗りつぶし帯・マーカーを含む）を写し、id は新しく、色は今のパレットの未使用の色にして、元の系列の直後に入れる。近似曲線は写さない（確認事項 1）。

生成コードの例（line、マーカー・不透明度・塗りつぶし帯）:

```python
# 系列1: X = 時間 [0]、Y = 平均 [1]
x = pd.to_numeric(df.iloc[:, 0], errors="coerce")  # 数値にできない値は NaN にする
y = pd.to_numeric(df.iloc[:, 1], errors="coerce")  # 数値にできない値は NaN にする
ok = x.notna() & y.notna()  # X か Y が欠けている行は描かない
fill_lower = pd.to_numeric(df.iloc[:, 2], errors="coerce")  # 塗りつぶし帯の下端: 最小 [2]
fill_upper = pd.to_numeric(df.iloc[:, 3], errors="coerce")  # 塗りつぶし帯の上端: 最大 [3]
ax.fill_between(x[ok], fill_lower[ok], fill_upper[ok], color="#FF4B00", alpha=0.25, linewidth=0, label="_fill")  # 塗りつぶし帯（凡例には出さない）
ax.plot(x[ok], y[ok], color="#FF4B00", linewidth=2.0, linestyle="solid", marker="s", markersize=24 ** 0.5, alpha=0.8, label="平均")
```

### 5.3 G4 注釈

- 節「注釈」を、注釈があるときだけ「系列」と「軸」の間に入れる。以降の節の番号は1つずれる（注釈がなければ今と同じ番号）。このため `_Builder.section()` が番号を振るように変える（§2.3）。
- 書き方: 文字は `ax.text(x, y, 文字, …)`（図の中の割合なら `transform=ax.transAxes`）、水平線・垂直線は `ax.axhline` / `ax.axvline`、帯は `ax.axhspan` / `ax.axvspan`（`linewidth=0`）。第2Y軸を選んだ水平線・横の帯・文字（データの座標）は `ax2` に描く。
- 凡例: 名前を入れた線・帯を凡例に入れる（第2Y軸の分も、今の「まとめて凡例にする」書き方でまとまる）。凡例を出すかどうかの判定にも含める。
- 検査（dataprep。日本語のエラー、`field` は「注釈NのX」など）: 未入力、数として読めない、日時として読めない（日時の X）、対数軸で 0 以下、日時の X なのに数を入れた（その逆も）。
- 文字の数式の誤りは、今の数式のエラー（`field` は「数式」）になる。
- 手順（`b.step`）に「注釈N」を足す。

```python
# ==== 5. 注釈 ====
ax.axhline(100.0, color="#000000", linewidth=1.0, linestyle="dashed", label="基準値")  # 注釈1: 水平線
ax.axvspan(pd.Timestamp("2026-01-10 00:00:00"), pd.Timestamp("2026-01-12 00:00:00"), color="#000000", alpha=0.2, linewidth=0)  # 注釈2: 縦の帯
ax.text(0.05, 0.95, "ピーク", transform=ax.transAxes, color="#000000", fontsize=FONT_SIZE)  # 注釈3: 文字（図の中の割合）
```

### 5.4 G5 近似曲線

- 計算は numpy の `np.polynomial.Polynomial.fit(x, y, 次数).convert()`（最小二乗。`np.polyfit` より、X の値が大きいときの桁落ちに強い。係数は低い次数から `fit.coef`）。R² は `1 - 残差平方和 / 全平方和`。
- 描く範囲は、近似に使った点の X の最小〜最大を 200 点。系列と同じ Axes（第2Y軸なら `ax2`）に、系列の直後に描く（系列と同じ `x` / `y` / `ok` を使う）。
- 式の文字は、生成コードの実行時に係数から作る。式を作る関数 `poly_text(coef)` を、式を表示するときだけスクリプトの冒頭に定義する（エラーバーの関数と同じ扱い）。係数は有効数字4桁（`.4g`）、R² は小数4桁。2次以上は `x$^{2}$` のように数式で上付きにする。利用者の文字列は、系列の名前（`literal()` を通す）だけ。
  - 凡例（`legend`）: 線の名前を「温度の近似: y = 1.234x + 5.678（$R^2$ = 0.9981）」にする。
  - 図の中（`text`）: 左上に、近似曲線の順に並べて書く（位置は固定。`ax.text(0.03, 0.97 - 0.07 * 番号, …, transform=ax.transAxes, va="top")`、色は線と同じ）。線は凡例に出さない。
  - 出さない（`none`）: 線だけ描き、凡例にも出さない。
- 使えない場合（日本語のエラー）: X が日時・文字列の系列、X の異なる値が「次数 + 1」個より少ない、Y がすべて同じ値（R² を計算できない）、系列が見つからない。棒グラフでは近似曲線を使わない（欄を隠す）。
- 対数軸でも、近似は線形の値で行う（対数軸の上では曲がって見える）。そのことを欄の補足に書く。
- 手順（`b.step`）に「近似曲線N」を足す。

```python
# 近似曲線1: 系列1（温度）の 1 次式（最小二乗。numpy）
fit = np.polynomial.Polynomial.fit(x[ok], y[ok], 1).convert()  # 係数は低い次数から（fit.coef）
r2 = 1 - np.sum((y[ok] - fit(x[ok])) ** 2) / np.sum((y[ok] - y[ok].mean()) ** 2)  # 決定係数 R²
x_fit = np.linspace(x[ok].min(), x[ok].max(), 200)  # 近似曲線を描く X（データの範囲を 200 点）
ax.plot(x_fit, fit(x_fit), color="#FF4B00", linewidth=2.0, linestyle="dashed", label="温度の近似: " + poly_text(fit.coef) + f"（$R^2$ = {r2:.4f}）")
```

- 目盛（5a）・注釈（5b）は、この軸の種類に従う。`barh` の縦軸は「何個おき」、注釈の Y は「何番目のカテゴリか」。

### 6.3 G7 グラフの種類（U4 の順）

1. **ステップ（`step`）**: line と同じ書き方に `drawstyle="steps-post"`（`pre` / `mid` / `post`）を足す。塗りつぶし帯は `fill_between(..., step="post")` で段に合わせる。line でできること（点の形・エラーバー・第2Y軸・近似曲線）はすべて使える。
2. **横棒（`barh`）**: 今の棒グラフ（1系列・複数系列を並べる）と同じ並べ方を横向きにする（`ax.barh`。複数系列は縦方向にずらす）。エラーバーは Y 方向の設定を値の誤差として横向き（`xerr=`）に描く。カテゴリは matplotlib の既定どおり下から並ぶ（上から並べたいときは、Y軸の反転（5a）を使う。欄の補足に書く）。
3. **積み上げ棒（`barStacked`）**: 複数系列を縦に積む。負の値は、正の値と別に下へ積む（正と負の段が重ならない）。欠けた値は 0 として積む。1系列なら普通の棒と同じ。エラーバーと第2Y軸は使わない（隠す）。
   ```python
   stack_pos = np.zeros(len(positions))  # 正の値を積んだ高さ
   stack_neg = np.zeros(len(positions))  # 負の値を積んだ深さ
   # 系列1: …
   v = bar_data["y1"].fillna(0.0).to_numpy()
   ax.bar(positions, v, bottom=np.where(v >= 0, stack_pos, stack_neg), width=0.8, color=…, label=…)
   stack_pos += np.where(v >= 0, v, 0.0)
   stack_neg += np.where(v < 0, v, 0.0)
   ```
4. **ヒストグラム（`hist`）**: 各系列の Y 列の値の分布。X 列は使わない（隠す）。区間は全系列で共通（`np.histogram_bin_edges(全系列の値, bins=区間の数 か "auto")`）。複数系列の並べ方は確認事項 1。データ元が違う系列も使える（行の対応は要らないため）。
5. **色分け散布図（`scatterColor`）**: scatter の点を、色分けの列の値で塗る（`ax.scatter(..., c=色の値, cmap=…, norm=color_norm)`）。色の範囲は全系列で共通（色分けの列の最小〜最大）で、カラーバーを1本付ける（`fig.colorbar(…, ax=ax, label=…)`）。凡例は系列を点の形で見分けるもので、凡例の点は灰色にする（色はカラーバーで読む）。色分けの列の数値にできない値は、その点を描かず警告する。第2Y軸は使えない（カラーバーと第2Y軸の位置がずれるため。隠す）。

- 「グラフの種類」の選択肢の表示は、今の `line` / `scatter` / `bar` を変えず、`step`、`barh（横棒）`、`bar（積み上げ）`、`hist（ヒストグラム）`、`scatter（色分け）` を足す。
- 種類ごとの設定（段の付き方、区間の数と確率密度、カラーマップとカラーバーのラベル）は、「系列」の区分の「グラフの種類」の下に、その種類のときだけ出す（`#stepGroup` / `#stepWhere`、`#histGroup` / `#histBins` / `#histDensity`、`#colorMapGroup` / `#colorMap` / `#colorbarLabel`）。色分けの列は系列カードの `series-<id>-color-column`。

### 6.4 G6 式で新しい列

- **場所**: 「注釈・解析」の区分の「計算した列」（`#computedList`、「+ 列を追加」`#addComputedBtn`。§2.5）。カード `computed-<id>` に、データ元 `-source`（2ファイル以上のときだけ）、名前 `-name`、式 `-expr`、雛形のボタン（正規化 `-tpl-normalize`、オフセット `-tpl-offset`、移動平均 `-tpl-rolling`）、削除 `-remove`。カードに「列 [N] として使えます」と、作った列の番号を出す。
- **文法**（新しいモジュール `py/mplgui/expr.py`。`pyscript.toml` の `[files]` に足す。`eval` も Python の `ast` も使わず、字句解析と再帰下降の構文解析を自前で書く）:
  - 数（`1`、`2.5`、`1e3`）、列（`[N]` か Excel の列記号の大文字 `A`=`[0]`、`B`=`[1]`、…、`AA`=`[26]`）、`+ - * /`、`**` と `^`（どちらもべき乗）、括弧、単項マイナス。優先順位と結合は Python と同じ（`-2**2` は `-(2**2)`）。
  - 要素ごとの関数（小文字）: `abs` `sqrt` `exp` `log`（自然対数）`log10` `sin` `cos` `tan`。
  - 集計（列 → 1つの値）: `min` `max` `mean` `median` `std`（標本標準偏差。pandas の既定）`first` `last`（欠けていない最初・最後の値）。
  - 系列の処理: `rolling_mean(式, 窓の幅)`（中心の移動平均。窓の幅は 1〜1000 の整数の定数）、`diff(式)`、`cumsum(式)`。
  - 上限: 200 文字、入れ子の深さ 30。式には列を1つ以上含める（列の無い式はエラー）。
  - 誤りは日本語のエラー（`field` は「計算した列Nの式」）。何文字目かを添える（例「5文字目: 閉じ括弧が足りません」）。知らない関数は、使える関数の一覧を添える。
- **参照できる列**: その計算した列のデータ元の、ファイルの列だけ（ほかの計算した列は参照できない。確認事項 2）。日時の列はエラー。数値にできない値は NaN として計算し、警告する（A7 と同じ形。桁区切り・小数点のヒント付き）。
- **計算する行**: 「描画から除外する先頭行」を除いた行（`max` や `first` もその行だけで計算する。確認事項 3）。
- **結果**: 0 での割り算・負の数の平方根などの ±inf / 計算できない値は NaN にする（生成コードは `with np.errstate(divide="ignore", invalid="ignore"):` の中で計算し、`replace([np.inf, -np.inf], np.nan)` する）。入力は数なのに計算できなかった値が出たときは、件数を警告する。
- **列の番号**: 計算した列は、そのデータ元の列の後ろに、カードの順に足す（ファイルの列が 5 個なら、最初の計算した列は `[5]`）。系列の X・Y、エラーバー・帯・色分けの列の選択肢に「名前 [5]（計算）」として出る。設定では `__idx__5`（今までどおり列番号）。
  - 計算した列を削除・データ元を変更したら、JS がその列を使う系列の列を空に戻し（警告する）、後ろの計算した列を使う系列の列番号を詰める。
  - ファイルの読み直しで列の数が変わったら、JS が計算した列を使う系列の列番号をずらす（計算した列を指したまま）。
- **生成コード**: 「描画に使う行」の後に「計算した列」の節を、計算した列があるときだけ入れる。利用者が書いた式は、`comment_text()` を通してコメントにだけ入れる。名前は `literal()`。
  ```python
  # ==== 3. 計算した列 ====
  with np.errstate(divide="ignore", invalid="ignore"):  # 0 での割り算などは警告を出さず、下で NaN にする
      # 計算した列1: 比（式: [1] / max([1])）→ 列 [5]
      calc = pd.to_numeric(df.iloc[:, 1], errors="coerce") / pd.to_numeric(df.iloc[:, 1], errors="coerce").max()
      df.insert(df.shape[1], "比", calc.replace([np.inf, -np.inf], np.nan), allow_duplicates=True)
  ```
  関数は決まった形で書く: `np.sqrt(…)`、`(…).max()`、`(…).dropna().iloc[0]`（first）、`(…).rolling(5, center=True).mean()`、`(…).diff()`、`(…).cumsum()`。数は `literal()`。
- **雛形のボタン**: 式の欄を `[N] / max([N])`（正規化）、`[N] - first([N])`（オフセット）、`rolling_mean([N], 5)`（移動平均）にする。N は、系列1の Y 列（同じデータ元のとき）か、なければ `[1]`。
- データ確認タブには、計算した列は出さない（読み込んだファイルの内容だけ）。

### 6.5 dataprep・codegen・runner の広げ方

- dataprep: 計算した列を `expr.py` で解釈し、データ元ごとに（`skipRows` を除いた）DataFrame の末尾に足してから、系列の計画を作る（列の範囲・数値の確認・警告は今と同じ道を通る）。グラフの種類ごとの計画（`PlotPlan` に種類別の小さな dataclass。`hist` の区間、`barStacked` の積んだ高さの範囲、`scatterColor` の色の範囲）を足し、軸の種類（`barh` の縦軸カテゴリ、`hist` の横軸）と `_Extents` を種類に合わせる。
- 自動描画（GUI 同期）では、生成コードが `df.insert` で列を足すので、読込済みの DataFrame をそのまま渡さず、コピーを渡す（計算した列があるときだけ。描画のたびに列が増えるのを防ぐ）。
- codegen: `SERIES_EMITTERS` に `step` / `barh` / `barStacked` / `hist` / `scatterColor` を足す（`step` は line の関数に `drawstyle` を渡す、`barh` は bar の関数を向きつきにする）。「計算した列」の節（`_emit_computed`）。
- runner `figure_summary`: 線の `drawstyle`、棒の向き（縦・横）と積んだ棒の数、カラーバー（ラベル・カラーマップ・範囲。カラーバーの Axes は要約の一覧に入れず、元の Axes の項目として出す）を足す。

### 7.3 G8 グラフの種類 第2弾

種類ごとに使う設定（§2.2。§6.2 の表に3列を足す）:

| 設定 | box | violin | heatmap |
|---|---|---|---|
| 系列の X 列 | – | – | ○ |
| X列（全系列共通。`#xColumn`） | – | – | – |
| Y 列 | ○（箱にする値） | ○（胴にする値） | ○ |
| 色分けの列（「値の列」） | – | – | ○（必須） |
| 点の形・点サイズ | – | – | – |
| 線幅 | ○（箱の縁・ひげ） | ○（胴の縁） | – |
| 線種 | – | – | – |
| 色 | ○（箱の塗り） | ○（胴の塗り） | –（カラーマップを使う） |
| 不透明度 | ○ | ○ | ○ |
| エラーバー・塗りつぶし帯・第2Y軸・近似曲線 | – | – | – |
| 注釈 | ○ | ○ | ○ |

1. **箱ひげ図（`box`）**: 系列ごとに1つの箱を、左から系列の順に 0, 1, 2, … の位置に描く（`ax.boxplot(..., positions=[0, 1, …], tick_labels=[凡例名, …], patch_artist=True)`。`tick_labels` は matplotlib 3.9 からの名前）。
   - 箱の塗りは系列の色と不透明度、縁・ひげ・中央値の線は黒。ひげは matplotlib の既定（箱の端から 1.5×IQR まで）。外れ値の点と平均の印は `plot.box` で切り替える。
   - 値は `pd.to_numeric(...).dropna()` にしてから渡す（NaN が混ざると中央値が NaN になるため）。数値にできない値は、今の系列と同じ形で警告する。値が無い系列は、位置を空けたまま描かない（警告）。
2. **バイオリン図（`violin`）**: 同じ並べ方で、系列ごとに `ax.violinplot(..., positions=[i])` を呼ぶ（系列ごとに色を付けやすい）。
   - 胴の塗りは系列の色と不透明度。端の線も系列の色。密度の推定は matplotlib の既定（Scott の方法、100 点）。
   - 実装時の変更: 中央値・平均の線は黒にした（系列の色では、塗りつぶした胴（既定の不透明度 1）の上で見えないため。箱ひげ図の中央値の線と同じ）。
   - 値が 2 個未満の系列は、密度を推定できないので描かない（警告）。
   - 箱ひげ図・バイオリン図の軸:
     - 横軸はカテゴリ（系列の凡例名）。目盛は「何個おき」、注釈の X は「何番目か（0 始まり）」で、棒グラフと同じ。
     - 縦軸は数値か対数。Y が日時の列はエラーにする。
     - 系列ごとにデータ元が違ってもよい（ヒストグラムと同じ）。
     - 自動の軸ラベルは、横軸が空。縦軸は、系列が1つならその Y 列の名前、2つ以上なら空。
     - 凡例は出さない（名前は目盛に出る）。向きは縦だけ（横向きは作らない）。
3. **ヒートマップ（`heatmap`）**: データの形は §7.8 の 2 で決める。推奨は案 H2（X・Y・値の3列の縦長の表から格子を作る）。
   ```python
   heat = pd.DataFrame({"x": x[ok], "y": y[ok], "z": c[ok]}).pivot_table(index="y", columns="x", values="z", aggfunc="mean")
   mesh = ax.pcolormesh(heat.columns.to_numpy(), heat.index.to_numpy(), heat.to_numpy(), cmap="viridis", shading="nearest")
   colorbar = fig.colorbar(mesh, ax=ax)
   ```
   - 同じ X・Y の組が複数あれば、平均を描く（件数を警告）。値の無いマスは塗らない。
   - X・Y は数値の列か文字列の列（文字列は現れた順にカテゴリとして並べる）。日時の列は 5d では使えない（日本語のエラー）。
   - X・Y の異なる値は、それぞれ 500 種類まで。多すぎるとマスが細かくなりすぎるうえ、格子でないデータを選んだ取り違えのことが多い。超えたら日本語のエラーにする（上限は計測して見直す）。
   - 系列は1つだけ。2つ以上はエラー（「ヒートマップは系列1つで描きます。」）。ヒートマップを並べるのは G9（5e）のパネルで行う。
   - H2 を推奨する理由: 色分け散布図と同じ3列（X・Y・色分けの列）を使うので、種類を切り替えても設定がそのまま使える。測定の格子（走査したマップなど）の縦長の表をそのまま描ける。
   - 案 H1（行列の表）: 表を行列として扱い、系列の Y 列を左から並べて列にし、行は X列（`#xColumn`）の値にする。「1列目が軸、残りの列が測定値」の表（分光の時間変化など）に向く。ただし列が多いと、系列を1つずつ足すことになる。

### 7.4 G10 任意関数のフィッティング

- 近似曲線のモデルに「任意の式」（`custom`）を足す。
- 式は G6 の解釈器（`expr.py`）に「モデルの式」の入口（`parse_model`）を足して解釈する。
  - 使えるもの: 変数 `x`、パラメータ `a`〜`e`（式で使ったものだけ。1つ以上）、数、`+ - * /`、`**`（`^`）、括弧、要素ごとの関数（`abs sqrt exp log log10 sin cos tan`）。
  - 集計・系列の処理・列の参照は、日本語のエラーにする。`x` を含まない式もエラー。
- 生成コード（近似曲線を描く位置は今と同じく、系列本体の直後）:
  ```python
  def fit_model_1(x, a, b, c):  # 近似曲線1の式: a * exp(-b * x) + c
      return a * np.exp(-b * x) + c
  fit_params, _ = curve_fit(fit_model_1, x[ok], y[ok], p0=[1.0, 1.0, 1.0], maxfev=10000)
  r2 = 1 - np.sum((y[ok] - fit_model_1(x[ok], *fit_params)) ** 2) / np.sum((y[ok] - y[ok].mean()) ** 2)
  x_fit = np.linspace(x[ok].min(), x[ok].max(), 200)
  ax.plot(x_fit, fit_model_1(x_fit, *fit_params), color=..., linewidth=..., linestyle=..., label=...)
  ```
  - 関数の本体は、解釈した木から決まった形で書く（`to_code`）。利用者が書いた式の文字列は、`comment_text()` を通してコメントにだけ入る。
  - `from scipy.optimize import curve_fit` は、任意の式の近似曲線があるときだけ冒頭の import に足す。「使い方」に scipy が要ることを書く。
  - 実装時の追加: `curve_fit` は、初期値のところで式が有限でない値になると、収束したように見せて初期値を黙って返すことがある。そこで `fit_y = fit_model_N(x[ok], *fit_params)` が有限か確かめ（`np.isfinite`）、有限でなければ ValueError にして、上の手順のメッセージに置き換える。
- 表示: 「温度の近似: y = a*exp(-b*x) + c（a = 1.234, b = 0.5678, c = 9.012、R² = 0.9981）」。
  - 式は、解釈した木から整えた形で書く（利用者の文字列そのままではない）。
  - パラメータは有効数字4桁で、実行時に `fit_params` から作る。
  - 表示先（凡例・図の中・なし）は今と同じ。
- エラー:
  - 収束しない（`curve_fit` の RuntimeError）、初期値で計算できない値になる（ValueError）は、手順（`Step`）で「近似曲線N: 式を当てはめられませんでした。初期値を変えてみてください。」に置き換える。
  - 点の数がパラメータの数以下のときは、dataprep が先に日本語のエラーにする。
  - X が日時・文字列の系列などは、今の近似曲線と同じ。
- scipy の読み込み（U5）: openpyxl と同じく、初めて必要になったときだけ `ensureScipy()` で読み込む。
  - GUI 同期では、描画・保存・コピーの前に、任意の式の近似曲線が使われていれば読み込む。進捗には「scipy を読み込み中…（初回のみ）」と出す。
  - 編集モードでは、コードに `import scipy` / `from scipy` があれば、実行前に読み込む。
  - 読み込めなければ、日本語のエラーにする（「scipy を読み込めませんでした。インターネット接続を確かめてください。」）。
  - コードだけの更新（`script`）では読み込まない。runner の ImportError の案内に scipy を足す。

### 7.5 G9 サブプロット（5e。方針だけ）

- 図の分け方は `plot.layout = {rows, cols}`（1〜4。既定は 1×1 で、今と同じ）。
- 系列ごとにパネルを選ぶ（`series[].panel`）。注釈もパネルを選ぶ。近似曲線は系列のパネルに描く。
- 生成コードは、`fig, axs = plt.subplots(行, 列, squeeze=False)` の後、パネルごとの節で `ax = axs[0, 1]` と置き直す。系列・注釈・軸・グリッドと凡例は、今の書き方をそのまま使う（第2Y軸もパネルごとに `ax2 = ax.twinx()`）。1×1 のときは、今のコードと1文字も変えない。
- 軸の設定（スケール・範囲・目盛）は全パネル共通。タイトルと軸ラベルは、パネルごとに上書きできる。グラフの種類も全パネル共通。
- (a)(b) のラベルは各パネルの左上に置く（`ax.set_title("(a)", loc="left")`。注釈の数え方を変えないため）。
- 詳しい設計（系列の無いパネル、色分け散布図のカラーバー、ヒストグラムの区間をパネルで共有するか、など）は、5d のマージ後に相談する。
