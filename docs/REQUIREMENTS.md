# matplotlib GUI 改善・機能拡充 要件定義書

- 作成日: 2026-10-07
- 対象リポジトリ: `mioupa/matplotlib_gui`（GitHub Pages で公開）
- 位置づけ: 既存実装（`index.html` 単体、PyScript 2024.11.1）を改修するための要件。実装が進んだら AGENTS.md / README.md をこの内容に合わせて更新する。

---

## 1. 目的

研究データ（CSV / TXT / XLSX）から、論文・学会発表にそのまま使える matplotlib の図を、ブラウザ上の GUI だけで作れるようにする。今回の改修では次の3点を狙う。

1. 現行の不具合と仕様とのズレを解消する。
2. 保守しやすい構成（ファイル分割、自動テスト）に作り替える。
3. 「出力品質」「データ取り込み」「グラフ表現・解析」の3分野を拡充する。

## 2. 決定事項（2026-10-07 にユーザーが決定）

| 項目 | 決定 |
|---|---|
| 利用形態 | **GitHub Pages の URL から使う**。`file://` で直接開く使い方はサポート対象外とする |
| ファイル構成 | **ファイルを分割**する（HTML / CSS / JS / Python パッケージ）。ビルド工程は設けない |
| テスト | **自動テストを導入**する（pytest による単体テストと、Playwright による E2E テスト） |
| Pythonコード(beta)タブ | **GUI 設定から matplotlib コードを生成して表示し、コピー・編集・実行できる機能に作り替える** |
| 優先する分野 | 出力品質（論文・発表）、データ取り込み、グラフ表現・解析 |
| 優先しない分野 | 操作性・再現性（設定保存、Undo、ズーム、オフライン化）。今回は後回しにする |

### 2.1 引き続き守る前提（AGENTS.md より）

- サーバー処理を持たない。計算はすべてブラウザ内の Python（PyScript / Pyodide）で行う。GitHub Pages は静的配信のみに使う。
- 読み込んだデータを外部に送信しない（研究データを扱うため）。
- 列の指定は列番号で行う（同じ名前の列があっても区別できるようにするため）。
- 自動読込・自動描画の操作感を保つ（「読み込む」「描画する」ボタンは置かない）。
- データ確認タブで、描画から除外される先頭行をグレーで表示する。
- `parentNode` 系エラーの抑制・回復処理は削除しない（必要な場合は範囲を絞る。A9 を参照）。

### 2.2 AGENTS.md から変える点

- 「実装ファイルは `index.html` 単体」「`index.html` を開くだけで動く」は廃止し、GitHub Pages 配信を前提にする。
- §12 の作業対象は絶対パスで書かれており、しかも実際の場所と合っていない。絶対パスはやめて「このリポジトリ配下のみ」と書く（ローカル環境のパスを公開リポジトリに載せないため）。

## 3. 現状の構成（2026-10-07 時点）

- `index.html` 1ファイル（2,937行）。内訳は CSS 約600行、HTML 約270行、JS 約620行、Python 約1,440行。
- PyScript 2024.11.1 を使い、パッケージは pandas、matplotlib、openpyxl を読み込む。
- 処理の流れ:
  1. ファイルを選ぶと、JS が `requestLoadColumns` を呼ぶ。
  2. Python の `_load_dataframe` が DataFrame を作り、グローバル変数 `CURRENT_DF` に保持する。
  3. 設定を変えると、JS が 250ms のデバウンス後に `requestRender` を呼ぶ。
  4. Python の `_create_plot_figure` が DOM から全設定を読み直して図を作り、dpi 100 の PNG にして `<img>` で表示する。
  5. 保存時は図を作り直し、dpi 120 で書き出す。
- AGENTS.md に書かれていない実装済み機能: 軸の対数表示と範囲指定（第2軸を含む）、余白指定、背景透過での保存、Pythonコード(beta)タブ、ダークモード（OS 設定に追従）。

## 4. 目標アーキテクチャ

### 4.1 ファイル構成（案）

```
index.html              画面のマークアップのみ
pyscript.toml           PyScript の設定（パッケージ、Python ファイルの配置）
icon.svg
css/style.css
js/main.js              エントリ（ES Modules）
js/state.js             設定オブジェクト（唯一の正）とその更新・購読
js/bridge.js            Python の呼び出し、描画要求の世代管理
js/ui/                  系列カード、色選択、タブ、データ確認表、ステータス表示
py/main.py              PyScript のエントリ。JS と Python の橋渡しだけを書く
py/mplgui/loader.py     バイト列から DataFrame を作る（文字コード、区切り、シート、前置き行）
py/mplgui/settings.py   設定スキーマ、既定値、検証、日本語エラーメッセージ
py/mplgui/codegen.py    設定から matplotlib コードを生成する
py/mplgui/runner.py     コードを実行し、Figure を画像（PNG/JPG/SVG/PDF）にする
py/mplgui/fonts.py      日本語フォントなどの取得と登録
tests/unit/             pytest（CPython と Agg バックエンドで実行）
tests/e2e/              pytest-playwright（ブラウザで実行）
tests/fixtures/         テスト用データ（UTF-8、BOM 付き、cp932、複数シートの xlsx、前置き行付きなど）
pyproject.toml          開発用の依存のみ（実行時には使わない）
docs/REQUIREMENTS.md    本書
```

### 4.2 設計方針

- **設定オブジェクトを唯一の正とする**: 画面の状態はすべて JS 側の設定オブジェクト（JSON。`version` を持つ）に集める。Python は DOM を読まず、受け取った設定 JSON だけで処理する。
- **描画経路をコード生成に一本化する**:
  - 描画は「設定 → codegen が matplotlib コードを生成 → 実行 → Figure」の1経路だけにする。
  - こうすると、画面に表示される図と書き出したコードの結果が必ず一致する。
  - 現在の GUI 経路とカスタムコード経路の重複（凡例、目盛、グリッド、軸範囲の処理）もなくなる。
  - 生成するコードは pandas、matplotlib、numpy だけを使う。独自ライブラリに依存させず、ローカルの Python でもそのまま動くようにする。
- **Python のロジックを純粋関数にする**: `loader`、`settings`、`codegen`、`runner` は `js` モジュールに依存させない。これによって CPython 上で pytest を実行できる。
- **バージョンを固定する**: PyScript、Pyodide、フォントの取得元は、すべてバージョンを固定した URL にする。
- **開発環境を Pyodide に揃える**: 開発用の pandas と matplotlib のバージョンは、Pyodide に同梱されているものに合わせる。

## 5. 機能要件

優先度は Must（必須）、Should（できれば今回）、Could（余裕があれば）の3段階。

### 5.1 不具合・仕様とのズレの修正（Phase 1）

| ID | 優先度 | 現状 | 要件・受け入れ条件 |
|---|---|---|---|
| A1 | Must | データ確認タブの行番号列 `#` と skipRows のグレーアウトが未実装。CSS（`.skipped-row`）だけがあり、`_render_data_preview` は `skip_rows` を受け取るが使っていない。初回コミットからこの状態 | 先頭100行に行番号列 `#` を表示する。描画から除外される行には `.skipped-row` を付ける。除外行数を変えたら、ファイルを読み直さずにすぐ反映する |
| A2 | Must | 同じファイルを選び直しても `change` イベントが発火せず、再読込されない | 読込後に input の値をクリアし、選択中のファイル名は別の場所に表示する。同じファイルを選び直したら再読込される |
| A3 | Must | 連続操作で描画が重なり、古い描画が後から終わって新しい結果を上書きすることがある | 描画要求ごとに世代番号を付け、最新の要求の結果だけを画面に反映する。E2E テストで設定を連続変更しても、最後の設定の図が表示される |
| A4 | Must | 起動中・読込中の操作は、通知なしに捨てられる | 起動中はローディング状態を表示する。準備ができたら、その時点の最新設定で1回描画する |
| A5 | Must | 文字コードは utf-8、shift_jis の順に試すだけ。BOM 付き UTF-8 だと先頭の列名に不可視文字が残る。機種依存文字（①、㈱など）があると失敗する | utf-8-sig、cp932 の順に試す（必要なら euc-jp も）。判定した文字コードを画面に表示する。すべて失敗したら、日本語で原因と対処を示す |
| A6 | Must | 日本語フォント（約16MB）の取得に失敗すると、通知なしに文字化け（豆腐）になる。しかも描画のたびに取得をやり直す。取得元は `@main` でバージョンが固定されていない | 失敗は1回だけ通知し、そのセッションでは再試行しない。取得元のバージョンを固定する。ブラウザキャッシュ（Cache Storage など）で再訪時の取得を省く |
| A7 | Must | 「1,234」や単位付きの値が NaN になり、通知なしに除外される | 数値に変換できず除外した件数を、系列ごとに警告として表示する |
| A8 | Must | カスタムコード実行時、GUI のタイトル・グリッド・スケールなどがコード側の設定を強制的に上書きする。`fig.axes[1]` を第2軸とみなすため、subplots を使うと誤動作する | Phase 2 のタブ刷新で解消する。ユーザーが編集したコードには GUI の設定を上書き適用しない |
| A9 | Must | `parentNode` を含むエラーをすべて握りつぶし、前の画像が残っていると「描画に成功しました」と表示する | 抑制処理は残す。ただし成功の誤表示はやめる。PyScript の更新後にこのエラーが再現するか確かめ、再現しない場合は削除するかをユーザーに確認する |
| A10 | Must | DeprecationWarning を全体で無視している。`_spawn_task` は作成したタスクの参照を保持していない | 無視する警告を pyarrow 由来のものに限定する。実行中のタスクは参照を保持する |
| A11 | Must | README に廃止済みの「描画する」ボタンが残っている。AGENTS.md に実装済み機能が書かれておらず、作業パスも誤っている | 各 Phase の完了時に README.md と AGENTS.md を実装に合わせて更新する |
| B5 | Must | Pyodide の起動中（十数秒以上）と描画中に何も表示されない | 起動の進み具合（パッケージ読込、フォント取得）と描画中の状態を表示する |
| B6 | Should | 系列カードのラベルが入力欄に関連付けられていない。タブに role/aria、ステータスに aria-live がない | ラベルと入力欄を関連付ける。タブに `role="tab"` と `aria-selected` を付け、ステータスを `aria-live` にする |
| B7 | Must | 系列を削除すると既定色が重複する。scatter から line に戻すと、自分で入れた点サイズ24が0に戻る。不正な入力には `invalid literal for int()` などの英語の生メッセージが出る | 既定色は使われていない色から選ぶ。点サイズはユーザーが変更していない場合だけ自動で切り替える。入力エラーはすべて日本語で、どの項目が悪いかを示す |

## 6. 画面要件（変更点）

- 左の設定パネルを「データ読み込み」「系列」「軸・目盛」「体裁（フォント・サイズ・プリセット）」「注釈・解析」「保存」の区分に整理し、各区分を折りたためるようにする（機能が増えるため）。
- 右側のタブは「プロット」「データ確認」「Pythonコード」の3つとする。
- ステータス欄には、成功、警告（除外件数など）、エラーを区別して表示する。

## 7. テスト要件

| 種別 | 実行環境 | 対象 |
|---|---|---|
| 単体テスト | CPython と pytest。matplotlib は Agg バックエンド | `loader`（各文字コード、区切り文字、シート、前置き行、桁区切り）、`settings`（検証とエラーメッセージ）、`codegen`（生成したコードが実行でき、期待する artist（線、点、エラーバー、凡例など）を持つこと） |
| E2E テスト | pytest-playwright（Chromium）とローカルの静的サーバー | 起動、`tests/fixtures` の読込、自動描画、設定変更での再描画、連続変更（A3）、データ確認のグレーアウト（A1）、保存、Pythonタブでの編集と実行 |
| 生成コードの一致確認 | CPython | 生成したスクリプトをローカル実行した図と、ブラウザで描いた図の要素（系列数、軸範囲、ラベル）が一致すること |

- 開発用の依存は `pyproject.toml` で管理する（uv の使用を想定）。
- 新しい機能を追加するときは、その機能の単体テストを必ず追加する。

## 8. 非機能要件

| 項目 | 要件 |
|---|---|
| 対応ブラウザ | デスクトップ版の Chrome、Edge、Safari、Firefox の最新版。スマートフォンでは表示が崩れない程度でよい |
| 起動時間 | F6 で計測した現状値より悪くしない。2回目以降の訪問ではフォントを再取得しない |
| 描画の応答 | 目標は、10,000行×5系列で設定を変えてから1秒以内に再描画すること（F6 の計測後に確定する） |
| データの扱い | 読み込んだデータを外部に送信しない。外部への通信は、ライブラリとフォントの取得だけにする |
| エラー表示 | 利用者の操作が原因のエラーは、日本語で原因と対処を表示する。内部エラーの詳細は折りたたみ欄に表示する |
| 依存 | CDN の URL はすべてバージョンを固定する |

## 9. フェーズ計画

| Phase | 内容 | 主な ID |
|---|---|---|
| 1 | 基盤の刷新と不具合修正 | F1–F6, A1–A11, B5–B7 |
| 2 | 描画経路のコード生成化と、Pythonコードタブの刷新 | P1–P7（A8 もここで解消） |
| 3 | 出力品質 | C1–C6 |
| 4 | データ取り込み | D1–D6 |

- Phase 2 を Phase 3〜5 より先に行う。描画経路をコード生成に一本化してから機能を足すことで、各機能の実装が1か所（codegen）で済むようにするため。
- 各 Phase は1本以上の PR にまとめ、完了時に README.md と AGENTS.md を更新する。
